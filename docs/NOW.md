## 設計上の選択（register）

> **問い: 「全実験を通して一度も変えていない選択はどれか」**（`変えた実績` が空の行）。
> それを上流から1本ずつ壊す実験を立てる。**「変えられない」と思っている行こそ最優先。**
> 🔴 **可否の判定式と 1手の primitive は、書いた/変えたその場でここに 1 行足す**（監査まで待たない）。
> なぜこの表が効くのか / 過去にこれを外して何が起きたかは `../CLAUDE.md`。

| ID | 選択（何を決めているか） | 現在の値 | 根拠 | 変えた実績 |
|---|---|---|---|---|
| DC01 | **1手で何ができるか**（出力の最小単位。**可否の `if` そのもの**） | | 惰性 | — |
| DC02 | 解の表現（内部状態の持ち方） | | 惰性 | — |
| DC03 | 何を最小化/最大化しているか（スコアの代理） | | 惰性 | — |
| DC04 | 構築順序（どれから決めるか） | | 惰性 | — |
| DC05 | 決めたものを後で動かすか（不可侵か） | | 惰性 | — |
| DC06 | 候補生成の粒度（近傍/遷移の定義） | | 惰性 | — |
| DC07 | 探索の枠組み（貪欲/ビーム/焼きなまし/DP） | | 惰性 | — |
| DC08 | 時間の使い方（1本を深く / 多スタート best-of） | | 惰性 | — |

- `根拠` は **測定 / 直感 / 惰性**（最初の実装のまま）の3値。**「惰性」かつ「変えた実績が空」が容疑者。**
- 行は問題に合わせて足す/割る（枝分かれは `DC05b`）。**1つの行が「✅ 変えた」になったら行を割る**
  ── 混ざっていた別の惰性が見えなくなる。
- **「問題の性質だから変えられない」と書きたくなったら条文に戻って確認する。**
- 変えたら `変えた実績` に印をつけ、結果は正なら `VERSIONS.md`、負なら下の棚へ。

## 否定結果の棚（**再監査の対象**）

> **否定結果は「その時の実装での」否定にすぎない。** バグ修正・機構追加・register の選択変更のあとは、
> 前提が変わった否定を再走させる（再監査しないと記録は死蔵になる。理由と実例は `../CLAUDE.md`）。

| ID | 否定したこと | 測定条件（`EX###` ＋ どの版・どの機構が有効/無効だったか） | これが無効になる条件 | 再監査 |
|---|---|---|---|---|
| NG01 | | | | 未 |

- 結論ではなく**前提つき**で書く。「A は効かない」ではなく「**B が無い状態では** A は効かない」。
- 🔴 **根拠の測定 ID（`EX###`）を必ず併記する** ── 再走のとき「前と同じ条件」を復元できるのはこれだけ。
- `これが無効になる条件` が書けない否定は原因が分かっていない ⇒ 切り分けてから載せる
  （分からないまま「効かない」と書くと、二度と触れない領域が増えるだけ）。
