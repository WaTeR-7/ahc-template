# 近似した世界の量で、条文の量を代用していないか

**主張**: 可否の `if` が**条文と同じ形**でも、**代入している変数が「近似した世界」の値**だと、条文より狭くなる。
⇒ 可否の判定を条文と突き合わせるときは、**式の形だけでなく、各変数が「どの世界の量か」**まで並べる。

## なぜ見つからないか

- 式は条文と同じ（`ℓ ≤ k + 1`）なので、**コードを読んでも「条文どおり」に見える**。
- 全ての版に共通なので、**A/B 比較には現れない**。register にも「条文どおり」と書いてある。
- 狭くなるのは特定の状況だけなので「**たぶん稀**」と思って数えない。

ahc068（配達を距離最短で実装）・ahc069（fit 条件を外接矩形全部空きに）の「条文より狭い」型の、**もう一段見えにくい形**。

## 実例（ahc072）

入れ直しの DP は、「x を抜いた世界」の操作列を進めながら x の経路を探す。跳べる距離の条件 `ℓ ≤ k + 1` の `k`（足元の匹数）を、
**x を抜いた世界の高さ**で数えていた。ところが x がそこに居ることで、抜いた世界では既に帰っているはずの者が塞がれて残っている形がある。
条文の `k` はその者も数える ⇒ **実装の `k` は条文より小さく、跳べる距離の上限が短かった**。

- 直した差は 71 行。**+0.58%（`t` 8.2）・+0.41%（`t` 5.8）**（独立な 2 集合）。受理した試行の **3〜4%** に入っていた（「稀」ではなかった）。
- 見つかったのは A/B でも register でもなく、**解法を 1 枚にまとめる文書を書いて、可否の `if` を条文と並べたとき**。

## 探し方

1. **近似した世界を列挙する**: 1 要素を抜いた世界 ／ 楽観的なモデル（時刻・順序を無視）／ 仮の状態（途中まで入れた解）／ 前計算した表（入力時点の量）。
2. 可否の `if` ごとに、**条文の変数 ⇔ 実装の変数 ⇔ その変数はどの世界の量か**の 3 列で書く。
3. 「近似の世界の量」が入っているセルについて、**条文の量とずれる状況を 1 つ作ってみる**（作れなければ同値）。
4. ずれる状況が作れたら、**診断カウンタで頻度を数える**。「たぶん稀」は数えるまで信じない。
5. 直す版は既定 OFF の env で作り（OFF で前の版と byte 一致）、paired で測る。**「壊れている ＝ 直せば伸びる」ではない**ので、1 つのレバーとして採否を決める。

## 限界

- 狭い点が見つかっても、**取り分が無いものもある**（ahc072: 続けて同じ向きに跳ぶ 2 手を 1 手につなぐ後処理は、つなげる組が 1 件あたり 0.135 しか無く +0.067%）。
  ⇒ 直す前に**供給を数える**（→ [「効かなかった」の切り分け](mechanism-failure-triage.md)）。
- 緩い側にずれている（条文より広い）場合は、最後の検査（公式の規則での再生）で落ちるので気づく。**気づかないのは狭い側だけ。**

## 適用条件

**軸に依らない**（プロセスの道具）。特に、**残りを固定して 1 要素の最適応答を解く**形（LNS・DP での入れ直し）と、
**楽観的なモデルで計画を作ってから実際に落とす**形で起きやすい。

**昇格状況**: **→ `CLAUDE.md` 済**（「条文より狭い」型は ahc068・ahc069・ahc072 の 3 回目）。
