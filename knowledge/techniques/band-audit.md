# 場合分けの「帯」は、入れた瞬間に表にして全部埋める

**主張**: 入力の性質でクラス分けして設定を変える設計にすると、
**後から足した帯の外側が、古い値のまま取り残される。**
バグではなく**「測っていない領域」**なので、テストにもレビューにも出ない。
⇒ 🔴 **帯を 1 つでも入れたら、`grep` で全部の帯を並べ、「どのクラスがどの値か」の表を作る。**

## 典型的な壊れ方

```rust
} else if (A..B).contains(&n) { X } else { Y }   // 半開区間の端で 1 つずれる
```

- 半開/閉区間の書き分け（`..` と `..=`、`>=` と `>`）で端が 1 つずれる。
- **後から上位クラスを足したのに、下位クラス用の分岐がそのまま残る。**
- 分岐が複数のレバーに散らばると、**どのクラスにどの証拠があるか**が誰にも分からなくなる。

## 手順（コストはほぼゼロ）

1. **全レバー × 全クラス**の表を作る（値と**根拠の測定 ID**を同じセルに書く）。
2. 🔴 **「値」ではなく「根拠が空のセル」を探す。** 空セルが赤字候補。
3. 空セルを埋める前に **🔴「そのクラスにその機構の仕事があるか」を数える**
   （作用対象が存在しないクラスに広げても null にしかならない）。
4. 表は盤面（`docs/NOW.md`）に置く ── **コードのコメントに書くと分岐と一緒に腐る。**

## 何が起きるか（この規律の効果）

- **証拠が最も厚いレバーほど、帯の外が放置されやすい**
  （効いたクラスで満足して次の軸へ移るため）。表を作ると一目で分かる。
- 帯を埋める作業は**新機構より安い**（env を 1 つ変えて掃引するだけ）のに、
  **効果は新機構と同等**になることがある。

## 限界・反例

- **仕事が無いクラスに広げても効かない**（作用対象の個数を先に数える。上の 3）。
- クラス分けそのものが正しいかは別問題。**クラス境界は、挙動が実際に切り替わる点に置く。**

## 実績

1 回で 2 度踏んだ。1 度目は帯の端が 1 つずれていた見落とし、
2 度目は**証拠が最も厚いレバーが半分のクラスで未測定**だった（埋めたら、その回で最大の当たり）。

**昇格状況**: 未（1 回目だが、同一回で 2 度）。
