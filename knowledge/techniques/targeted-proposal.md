# 近傍集合は足りている。足りないのは「引く確率」

**主張**: 局所探索が凍って見えるとき、**必要な手は既存の近傍集合の中にあるのに、
乱択がそれを引く確率が絶望的に低いだけ**のことがある。
⇒ **近傍を大きくする前に、「欲しい結果から逆算した手」を提案分布に混ぜる。**
**逆算のコストが 1 手の適用と同じオーダーなら勝てる。**

## 適用条件（構造カルテの軸で）

- **軸3a**: 1 手が局所操作なのに**効果は大域**（1 手で構造が繋がる/切れる）
- **軸5 に干渉がある**：良い解ほど「動かすと壊れる」要素の割合が高くなる
  （⇒ 収束後は乱択の当たりが原理的に減る）
- **軸8 の感受性が低い**（反復を増やしても伸びない）＝ 引く確率が律速している兆候

## 手順

1. **欲しい結果を 1 つ選ぶ**（満たせていない制約・繋がっていないペアなど）。
2. **それを実現する手を逆算して列挙する**（構造をたどるだけ。探索しない）。
3. **近傍集合は変えず、提案分布だけ差し替える**（一定確率でこの手を提案する）。
4. **候補が出た回数と、出たときの受理率を数える。**

## 🔴 律速がどこかを数字で切り分ける

| 数える量 | 読み方 |
|---|---|
| `ask`（逆算を試した回数）| 分母 |
| `hit`（候補が 1 本以上出た回数）| **これが数 % なら、律速は「選び方」ではなく「候補の存在」** |
| `acc`（出た候補の受理率）| ここが高いなら供給を増やすほど効く |

🔴 **候補が普段 0〜1 本しか出ないなら、「どれを選ぶか」を工夫するレバーは全部 null になる**
（実際、選び方の軸を 3 通り変えても net ≒ 0 だった）。**選択肢の数を疑う。**

## 射程を広げるときの順番

**同じ要素の中 → 隣接要素 → k 要素の経路**、と**費用が線形に増える順**に広げる。
広げるたびに `hit` を測り直す ── **射程を広げても `hit` が伸びなければ、それは幾何の問題ではない。**

## 限界・反例

- **候補が構造的に複数出る機構では「幅」を増やすのが効く**が、
  **0〜1 本しか出ない機構では幅を増やすと単調に悪化する**（同じ回で両方観測した）。
  ⇒ **幅のレバーは、候補数の分布を見てから振る。**
- 提案分布を偏らせると**壊す量も同時に増える**ことがある（当たりの手が既存の成果を壊す型のとき）。
  ⇒ [原子的な複合手](atomic-two-stage-move.md) と組む。

## 実績

**乱択 → 逆算に変えるだけで、同じ近傍集合のまま大きく伸びた**（この回で最大の当たり）。
射程を 1 段広げる改造も当たった。
