# 「機構が効かない」を 3 段に割る ── 実装 / 置き場所 / 供給

**主張**: 新機構が null だったとき、原因は**独立な 3 つ**のどれかで、**順に潰さないと
「機構が悪い」と誤って確定する**。3 段のうち **2 段目と 3 段目は差分に現れない**ので、
A/B を何本回しても見えない。

| 段 | 問い | 潰し方 |
|---|---|---|
| ① **実装** | 機構は設計どおり動いているか | 🔴 **機構の定義そのものを assert にする**（「この手を当てたら、狙った性質が成り立っているか」）。一度も落ちなければ実装は白 |
| ② **置き場所** | 作った改善は**提出する解**に載るか | 探索が「現在解」を良くしても、**提出するのは best 解**。受理率が高い探索や引き戻し閾値が緩い設計では、**現在解は best から遠く**、そこでの改善は best に載らない |
| ③ **供給** | その手は**良い解に存在するか** | 🔴 **同じ機構を最終解に対して回し、候補の本数を数える**。0 本なら探索の質をいくら上げても意味がない |

## 適用条件（構造カルテの軸で）

- 軸1 = 配置/割当（局所探索が乗る形）で、**新しい近傍・複合手を足したのに null** のとき
- 軸5 に干渉がある（＝ 1 手が他の決定を壊す）と ③ が起きやすい

## ①の作法 ── **機構の定義を assert にする**

「差分構造が壊れていないか」ではなく、**その機構が主張していることそのもの**を書く
── **その手を当てた直後に、狙った性質が本当に成り立っているか**を実走行中に検査する。
byte 一致は「違う」しか教えないが、この assert は**どの入力でどう違うか**を教える。
⚠ **これが無いと、②③の切り分けに入る前に「実装のせいかもしれない」が残り続ける**（切り分けが進まない）。

## ②の見分け方

**受理率と引き戻し閾値を見る。** 受理率が高い（悪化手をほとんど受理している）区間では、
現在解は best から大きく離れている。**そこに +1 の改善を注いでも best は更新されない。**
⇒ **良い解を直す機構は、探索の中ではなく「best 解に対して」当てる。**
⚠ 多くの実装で、最終磨きは**最小の近傍しか持っていない**（それだけでも大きく伸びることがあるので、
そこが弱いことに気づけない）。

## ③の測り方（**最重要。ここが一番安い**）

**最終解に対して機構を 1 回走らせ、`ask` と `hit` を数えるだけ。**
0 本なら、直すべきは機構ではなく**手の定義**（→ [原子的な複合手](atomic-two-stage-move.md)）。

## 限界・反例

- 3 段を潰しても null なら、それは本当に「効かない機構」。**否定の棚に前提つきで載せる。**
- ③が「良い解には存在しないが、悪い解には大量に存在する」形のとき、
  **探索の序盤だけ発火して統計に紛れる**ことがある。**発火の位相分布も数える。**

## 実績

1 回（相対評価の回）。**①は白、②と③が原因**という切り分けが、
「機構を捨てる」ではなく「手の定義を変える」という次の一手を出した。
