# 盤面を bit で持ち、「置ける位置の集合」を一括で作る

**主張**: 幅 ≤ 64 の格子なら **1行 = 1語**で持てる。すると「この形をこの行に置ける `y` の集合」が
**行数 × O(log 幅) の語演算**で丸ごと求まる。⇒ **「形カタログ × 全位置」を毎ターン総当たりできる**ようになり、
**種からサンプリングして育てる探索を、カタログ上の総当たりに置き換えられる**。

🔴 **効き目の本体は速度ではなく「探索のクラスが変わること」。** そこを取り違えると、
（ahc069 のように）**時間が余っている問題に入れて 0 で終わる。**

## 適用条件（構造カルテの軸で）

- **軸1 = 配置 / 割当**（または対話＋オンライン配置）で、毎手「多数の形 × 多数の位置」の**可否**を判定する
- **軸3: 1手が占めるのが矩形とは限らない**（任意形・凸形・階段形）
  ── ⚠ **矩形だけなら 2次元累積和で同じ O(1)** が得られるので、bit にする価値は小さい（ahc069 はこれ）
- **軸8: 候補数に対する感受性がまだ残っている**（＝ 候補を増やすと伸びる。**先に測る**。飽和していたら無意味）
- 盤面幅 ≤ 64（AHC の `N = 30〜64` はほぼ該当。50×50 なら盤面全体でも 40 語）

## 中核の 2 つ（ここだけ覚えれば移植できる）

**① 連続 `L` セルが空いている開始位置を O(log L) で作る**

行の空きマスクを `f` とすると、`f &= f >> 1` を繰り返すと「**そこから右に 2, 3, … セル連続で空き**」の
開始位置マスクになる。倍々（`f &= f>>1; f &= f>>2; f &= f>>4; …`）で **`L` 連続空きの開始位置が O(log L)**。

**② 形の各行の「開始位置マスク」を、形の中でのズレぶんシフトして AND する**

各行が 1 本の区間である形（＝ 直交凸。矩形・部分行つき矩形・階段はすべてこれ）なら、
形の行 `r` が原点から `a_r` ズレて長さ `len_r` のとき

```
valid_y = ⋂_r ( runstart(free[x + r], len_r) >> a_r )
```

で **アンカー行 `x` に置ける `y` が 1 本のマスクとして出る**。あとは立っているビットを取り出すだけ。
`y` を 1 つずつ試す実装に比べて内側ループが**幅ぶん（〜50倍）消える**。

**付随して安くなるもの**: 占有との衝突は AND ／ セル数は popcount ／
**マスクそのものを鍵にした重複除去**（同じ領域集合に二度到達しない。Zobrist の代わりになる）。

## 組で使うもの: 2段評価

**マスクで安くなるのは「可否」だけで、「評価」は安くならない。**
露出・時刻クラスタ・窓の数といった数値評価は結局 候補数 × O(1) の計算が要る。
⇒ **粗い評価で上位 K に絞り、詳細評価はそこだけ**（ahc069 の 5位解法はこの 2 段構え）。
位置に依らない部分（形カタログ、形ごとの行マスク）は**起動時に前計算してキャッシュ**する。

## 効果 / 実績

- **未実績**（自分ではまだ使っていない）。ahc069 の上位 2 解法（5位 / 137位）がともに採用しており、
  5位は「人数ごとに最大 288 形 × 配置候補 ~1649 件をキャッシュ」という規模を毎ターン回している。
- 同じ回で自分は **2次元累積和**（矩形限定の O(1) 可否）で戦い、**153位 → 延長戦で 129位**。
  上位との差は **池が散らばった盤面ほど開いた（7.0% → 15.5%）** ＝ **矩形が置けない盤面での任意形の作り方**が差の本体。

## 限界・反例（🔴 ahc069 では入れても点にならなかった、と実測で言える）

- **時間が律速でなければ、速くなっても点にならない。** ahc069 の自分の版は
  **直列で 682ms / 1900ms しか使っておらず**（時間が 3 倍余っている）、
  それでも**仕事を増やす方向の最大が +0.13%**（箱の予算。しかも基数を上げすぎると壁時計の弁で自壊して **−0.74%**）、
  **減らす方向は ±1se 以内**（種の数・再配置候補数・目標数・オフセット数）。⇒ bit 化で浮く CPU に使い道が無い。
- **同一周長の「形の多様性」を足しただけでは +0.03%** だった（余りを上下 2 行に割る形族）。
  ⇒ **カタログを作ること自体が目的ではない。** 効くのは「サンプリング → 総当たり」に**探索の型が変わる**とき。
- **矩形しか置かない問題では累積和で足りる**（実装が軽く、しかも「空きセル数」も O(1) で取れる）。
- 幅 > 64 だと複数語になり、シフトの繰り上がり処理でコードが急に汚くなる（速度も落ちる）。

## いつ判断するか

**軸1〜3 を埋めた段階（着手前）。** 「任意形を置く」「毎手たくさんの候補を見る」が読めたら、
**土台を最初から bit で組む**。⚠ **後から差し替えるのが一番損**
（ahc069 では累積和で組んだ後に任意形が必要になり、行ごとに範囲和を撃つ形に退化した）。
