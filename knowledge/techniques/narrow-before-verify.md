# 候補は事後に検証せず、事前に狭める

**主張**: 「候補を作る → 適用してみる → 壊れていたら却下」は、却下率が上がるほど探索が空回りする。
**候補生成の段で制約を張って、成立するものだけを作る。**

## 適用条件（構造カルテの軸で）

- **軸5 に干渉がある**（決定が後の自由度を削る／実行可能性の制約がある）
- 探索の**却下率が高い**（ahc068 では 82〜88%）。まず却下率を測ること ── これが低ければ別の場所が律速

## 見分け方（先に切り分ける）

却下率が高いとき、原因は3つに分かれる。**推測せず内訳を数える**:

1. **モデル誤り**（そもそも実現不可能なものを候補にしている）
2. **制約の張り忘れ**（実現可能なのに検証で落ちている）← ahc068 はこれが 96〜98%
3. コスト評価の誤り

ahc068 では「不正矩形 0 件・コスト失敗 0 件・確定破壊 96〜98%」と出たので、**2番だと確定してから**直した。

## 機構（ahc068 の例、2箇所）

- **確定済みを壊さない上限を、候補の段で `ext` に焼き込む。** 確定した対象の軌跡を時間方向に遡り、
  各操作の伸ばせる範囲を切り詰める。⇒ 却下率が落ちるだけでなく、**以前「効かない」と判定していた設定が
  逆転した**（ゲート再掃引で **+49M**、セッション単一の最大ジャンプ）。
- **時刻依存の禁止集合 `forb[t]`。** 時刻 t に挿入した操作が動かすのは「**その時刻にそこに居たもの**」なので、
  **最終位置で判定するのは誤り**。確定済み対象の**軌跡**が時刻 t に占めるセル集合を持つ（世代スタンプで
  クリア不要、再構築は #確定 × T）。⇒ 採用率 10-40% → **29-70%**、6 seed で −0.16% → **−3.89%**。

## 効果（ahc068）

**+49M**（狭めを入れた後に、否定済みだった設定を再走させた分）＋ 相乗りの採用率が 2〜3 倍。

## 一般化された教訓

**「事前に狭める」を入れたら、それ以前の否定結果は前提が変わっている**（→ `CLAUDE.md` 記録の規律）。
ahc068 では狭めの実装が過去の否定を無効化し、その再走が最大の利得だった。

**昇格状況**: 「否定の再監査」の側は **→ CLAUDE.md 済**。
「事前に狭める」自体は未昇格（ただし ahc068 内で**同じ構造が2回**出た ⇒ 昇格候補）。
