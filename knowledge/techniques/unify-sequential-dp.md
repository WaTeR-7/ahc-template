# 逐次適用を1つの DP に統合する

**主張**: 「探索して適用 → また探索して適用」と段を分けて回すと、**前の段が後の段に不利な決定を確定させる**。
複数の手段を**1つの値関数**にまとめると跳ねる。

## 適用条件（構造カルテの軸で）

- **軸1 = 操作列**で、複数の改善手段が**同じ資源（操作列そのもの）を書き換える**
- 各手段を単独で実装済みで、**それぞれは正の効果が出ているのに合計が期待より小さい**
  （＝段の間で食い合っている兆候）
- 統合後の状態空間が現実的（ahc068 では「対象の位置 × 操作時刻」）

## 機構（ahc068 の例）

相乗り（無料で進む）と挿入（1手払って進む）を**別々の探索**で回していたのを、1つの後退再帰にした:

```
h[T][p] = cost_to_home[p]
h[t][p] = min( h[t+1][ride(p)] ,  1 + min_{q∈N(p)} h[t][q] )
        ＝ min( 無料で相乗りして次の時刻へ , 1手挿入してこの時刻内で移動 )
```

スライス内の緩和は値が小さい整数なので**バケットの多点始点 BFS**で解ける。

## 効果（ahc068）

- 貪欲（段を分けた逐次適用）は **joint 最適の 3.46 倍**の手数を使っていた（計測で先に確認）。
- 統合＋高速化で **est 1020.98M → 1035.61M（+14.63M、97勝3敗）**。実ジャッジ 1,030,035,129。
  **公表されていた「相乗り＋自由度」の到達点（自由度のみの段階）を +15M 上回った。**

## 落とし穴

- **統合したものを貪欲の「後」に走らせると意味がない**（−0.52% しか出なかった）。
  貪欲が既に最適でない決定を列に確定させているため。**貪欲を置き換える位置に置く。**
- 1カードあたり O(T × 状態数 × 近傍) で**重い**。ahc068 では「時刻を間引く」ことで品質同等・時間半分に
  なった（**間引くのは O(N) の段だけ、O(1) の段は全解像度で残す** ── どちらがどちらかは計測で決める）。
- 打ち切りを壁時計でやると解が非決定的になる（→ `CLAUDE.md` 検証と計測の作法）。

## 出典

**統合すべきだという判断は自分の推論**（①②③を持っていて公表値に届かない理由を「逐次に適用しているから」
と読んだ）。統合される個々の手段のうち、相乗りと自由度は AHC068 writer の想定解に由来する
（→ [ride-along](ride-along.md) の出典欄）。
