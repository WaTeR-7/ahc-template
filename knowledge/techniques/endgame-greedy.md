# 終盤は探索を切って貪欲にする

**主張**: 構築の終盤は**動ける範囲が狭い**ので、探索してもほとんど選択肢が無い。にもかかわらず状態数は
残っているので**重いだけ損**。閾値で貪欲に切り替え、浮いた予算を序盤に回す。

## 適用条件（構造カルテの軸で）

- **軸1 = 操作列**（1つずつ確定していく構築）
- **軸5 に干渉がある** ── 確定が進むほど自由度が減る構造。**終盤の探索の価値が構造的に下がる**のはこのため
- **オーバーヘッドが前半に集中している**（測って確認する。ahc068 では**最初の25%のカードが T の34%**を消費、
  第1四分位は 3.13 手/枚）

## 機構

「残り未確定数 < 閾値」で探索を打ち切って貪欲に落とす（`AHC_*` の env で閾値を外出しし、掃引して決める）。
**逆向きの効果に注意**: 閾値を下げる（＝より多くを探索に回す）方が良いこともある。ahc068 では高速化で
予算が空いた後、閾値 8 → 3 に**下げる**のが最良だった（6 seed 合計 T: 8721 → 8337）。
⇒ **閾値は「切る/切らない」ではなく、空いた予算の配分先として掃引する。**

## 効果（ahc068）

閾値を全開（＝終盤を貪欲に）にした再掃引で **est +49M**。ただしこれは
[narrow-before-verify](narrow-before-verify.md) を入れた後の再測定で得た値で、
**狭め導入前は「効かない」と判定されていた**（否定結果は前提つきでしか意味を持たない実例）。

## 出典

「終盤は探索が重くなる割に動ける範囲が狭いので貪欲で良い」は **AHC068 の writer が述べていた**方針
（ユーザー経由で伝達）。実装と閾値の掃引は自作。
