# 記録の規律（`docs/NOW.md` を嘘にしない）

> **これは `CLAUDE.md` の規則の「長い版」**（根拠・失敗例・数字つき）。`CLAUDE.md` には短い形だけがある。
> **いつ読むか**: 否定を棚に載せる・「効かなかった」と書く・盤面を凍結する・提出を記録する、の前。
> 規則を足すとき・直すときは、**長い版をここに書き、`CLAUDE.md` には 1〜2 行だけ**置く（両方に全文を書かない）。
> 文中の `EX###`・`NG##`・`DC##` は、その回の private repo の `docs/` の ID。

- **🔴 記録する時刻はすべて JST で書く**(`2026-08-07 22:41 JST` の形)。
  **「残り n 日」のような相対量は、書くたびに絶対時刻から計算し直す**(放置すると静かに嘘になる)。
- **`docs/NOW.md` の「設計上の選択」register を維持する**。実装の選択を**問題の性質として書かない**
  (共通部品に昇格した選択は**問題の性質の語調で書かれる**ため、どの A/B 比較にも写らず計測規律を
  すり抜け続ける)。**レバーが連続して負に出たら「近最適に収束した」と読まず、`変えた実績` が空の行を
  上流から壊す** ── **レバー全滅は収束の証拠ではなく、共通の上流前提を疑う合図**
  (ahc068 は配達 primitive がこれで、5つのレバーが全滅したのを「収束」と読んだが、実際は全部が
  1つの未検査の選択の下流だった)。
  🔴 **可否の判定式と 1手の primitive は、書いた/変えたその場で register に 1 行足す**(監査まで待たない)。
  **待つと「共通部品なので誰も*選択*だと思っていない」状態が固定する** ── これが 2 回とも起きた形。
  **🔴 1つの行が「✅ 変えた」になると、同じ行に混ざっていた別の惰性が見えなくなる** ⇒ **変えた時に行を割る**
  (ahc069: 「候補生成」を形族と位置に割ったら +9.6%)。**register に持つ行は評価関数や候補生成だけでなく、
  「可否の判定式」そのものも含める。**

#### 「効かなかった」を確定させる前の 4 段 (ahc069 で全部踏んだ)

> 🔴 **新機構が null のときは、さらに「実装 / 置き場所 / 供給」の 3 段に割る。**
> ①**実装**は*機構の定義そのものを assert にして*白黒をつける ／ ②**置き場所** ── 探索の中で作った改善は
> **提出する best 解に載らない**ことがある(受理率が高い区間では現在解は best から遠い) ／
> ③🔴**供給** ── **同じ機構を最終解に対して回し、候補の本数を数える**。0 本なら探索の質は無関係。
> → [`knowledge/techniques/mechanism-failure-triage.md`](../techniques/mechanism-failure-triage.md)

1. **出力が変わったか確認する。** 変わっていないなら実装が無効化されている。変わっているのに net が 0 なら
   **勝ちと負けを同数生んでいる** ⇒ **勝敗の件数を必ず併記する。**
2. **項の値を 1 度は印字して目視する**(ahc069 は判定が常に true ＝ 別の量を数えていた)。
   🔴 **これは env レバー自身にも適用する** ── **掃引を投入したら「その env が実際に何になったか」を
   1 回印字する。** `.max()` / `.clamp()` の床・天井に飲まれていると、**レバーは存在しないのに
   掃引は `null` としか出さず**、しかも**過去の掃引の解釈まで遡って壊れる**
   (そのとき測っていたのは値ではなく「床に当たるか否か」だった、という形になる)。
   → [`knowledge/techniques/silent-clamp.md`](../techniques/silent-clamp.md)
3. **ただし「壊れている ＝ 直せば伸びる」ではない** ⇒ **バグ修正も 1 つのレバーとして paired で測ってから採否を決める。**
4. **同じ選択の基準を 3 通り試して全部 net ≒ 0 なら、「基準」ではなく「選択肢の数」を疑う**
   (ahc069 の律速は**候補の 18.3% しか成立しない**ことだった)。
- **否定的結果は「前提つき」で `docs/NOW.md` の否定の棚に記録する**(「A は効かない」ではなく「**B が無い状態では**
  A は効かない」)。🔴 **棚に載せるとき `NG01, NG02, …` の ID を振る**(候補 ＝ register の行は `DC01, …`。記号の一覧は [`docs-layout.md`](docs-layout.md))。
  🔴 **否定には根拠の測定 ID(`EX###`)を必ず併記する** ── 再走のとき「前と同じ条件」を復元できるのはこれだけ。
  **ID は一度振ったら動かさない**(枝分かれは `DC05b`)。**再走の指示・コミットメッセージ・証拠の見出しを
  この ID で結ぶ ⇒ `grep -rn NG27 .` が索引になる**([`docs-layout.md`](docs-layout.md)。手書きの索引表は分割のたびに腐る)。**バグ修正・機構追加・register の選択変更のあとは、前提が変わった否定を再走させる**
  (否定は永久ではない。ahc068 では否定済み実験の1本の再走が**単一最大の +49M**。記録していても
  再監査しなければ死蔵になる)。「機構が悪い」と「自分の実装が悪い」を切り分けずに否定として確定しない
  (ahc068: 却下率 85% の原因は機構ではなく制約の張り忘れだった)。
- **枠組みが反証されたら盤面を凍結する。** 🔴 **`NOW.md` は名前を変えない** ──
  **中身を `docs/frozen/<日付>-<何の盤面か>.md` へ切り出してから `NOW.md` を書き直す**
  (`LOG.md`→`LOG2.md` 方式は**凍結の瞬間に既存の全参照が静かに古くなる**。ahc069 で実際に起き、
  索引は自ら「節番号は分割前のまま」と書いていた)。**生きているファイルの名前は不変に保つ。**
  **凍結したスナップショットの冒頭に「以後の前提として再利用してはいけない結論」の表を置く**
  (否定された結論が新しい推論に紛れ込むのを防ぐ)。
  🔴 **凍結時に「コピーして引き継ぐ」ものが出たら、それは盤面ではなく前提**(用語集がこれ)
  ⇒ **コピーせず `SETUP.md` へ移して両方から参照する**(コピーした瞬間に二重管理になる。[`docs-layout.md`](docs-layout.md))。
  **凍結する必要があるのは「その時点の判断」だけで、定義や条文は凍結の対象ではない。**
- 🔴 **提出の記録は、「どの版を出したか」をユーザーに確認してから書く**(ahc072: 再提出を新しい版の結果と取り違えて記録し、「見込みと逆向き」の原因調査を 1 本立てた。
  測定自体は無駄にならなかったが、動機が誤り。提出#17)。**記録を一括で書き換えるスクリプトは、照合(assert)を全部通してから書き込む**(途中で落ちると、一部の文書だけ更新されたコミットになる。2 回踏んだ)。
- **順位表から読んだ数字は「その時点のスナップショット」として記録する**(上位は伸びるので目標値として固定しない)。
  **投資先は自分の赤字の構造で決める。**
- **コミットのたびに `docs/HISTORY.md` に1行追記。**
