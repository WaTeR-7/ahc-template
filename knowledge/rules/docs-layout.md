# 記録の置き場所と ID の規律

> **これは `CLAUDE.md` の規則の「長い版」**（根拠・失敗例・数字つき）。`CLAUDE.md` には短い形だけがある。
> **いつ読むか**: `docs/` を割る・ファイルを足す・ID を振る・盤面が膨らんできた、のどれかの前。
> 規則を足すとき・直すときは、**長い版をここに書き、`CLAUDE.md` には 1〜2 行だけ**置く（両方に全文を書かない）。
> 文中の `EX###`・`NG##`・`DC##` は、その回の private repo の `docs/` の ID。

- 🔴 **割る軸は 2 本**: ①**更新のされ方**(書き換える / 追記する / 不変) ②**読み直す単位**。
  **粒度は「書く単位」ではなく「読み直す単位」に合わせる** ── 分割の目的は書きやすさではなく、
  **前提が変わったときに読み直す範囲が 1 ファイルに収まること**(再走の規律は [`recording.md`](recording.md))。
- 🔴 **`docs/` は最初から分けてある**(要求が正反対なので同居させられない。地図は `docs/README.md`):
  **`NOW.md` = 盤面**(序盤チェックリスト/register/否定の棚/現行ベストと次の一手。**書き換える**。目安 150 行) ／
  **`EVIDENCE.md` = 証拠**(測定の全記録 `EX###` と実ジャッジ校正。**append-only**) ／
  **`SETUP.md` = 前提**(問題/構造カルテ/**用語集**/実行方法/env。ほぼ不変) ／
  **`VERSIONS.md`・`HISTORY.md` = 台帳** ／ **`frozen/` = 凍結スナップショット** ／
  **`SURVEY.md` = 過去回の調査**(`SV1`…。書き切り・詰まったときに読む。要るときだけ作る)。
  🔴 **育っても「移動」は起きない** ── 移動・改名は**その瞬間に既存の参照を全部腐らせる**
  (ahc069: 途中で `docs/` へ移し、さらに `LOG`→`LOG2` で 2 度腐らせた)。**増えるのは下の 1 回だけ。**
- 🔴 **証拠がさらに育ったら「族ごとに 1 ファイル」へ割る**(`docs/evidence/<族>.md`。索引は `docs/evidence/README.md`)。
  **1 つのファイルに「族順」と「append-only」を同時に課してはいけない ── 両立しない。**
  本戦中は追記位置を決める余裕が無いので必ず末尾に積まれる(ahc069: 4 本が族に入りそこねて G と F の間に
  取り残され、見出し `F` が 2 つになった)。**族ごとに割れば「末尾に追記」＝「族順」が自動で一致し、
  追記のたびの判断が消える** ── **本戦中に判断を要求する規律は必ず破られる。**
  ⚠ **1 実験 1 ファイルまでは割らない。** ahc069 で効いたのは「repack の知見を 8 箇所から 1 節に集めた」ことで、
  細かくするとその勝ちを戻す。**族 ＝ 再監査の単位**が粒度の下限。
- 🔴 **盤面は割らない。代わりに行数上限(目安 150 行)を課して台帳を押し出す。**
  盤面は毎セッション読むので、割ると「現在地を知るのに 5 ファイル開く」になり**逆に悪化する**。
  押し出す先: **版の一覧 → `VERSIONS.md`** / **変更履歴 → git log(または `HISTORY.md`)** / **用語集 → `SETUP.md`**。
  (ahc069: 盤面が 851 行 155KB まで膨らみ、**盤面本体は全体の 12%**、残りは台帳と辞書だった。
  履歴を押し出したのは**最終日**。**用語集を盤面に置いたせいで、凍結時に新ログへコピーされて二重化した**)。
- 🔴 **住所は「節番号」ではなく「ID」にする。一度振ったら動かさず**(枝分かれは `DC05b`)、
  **見出しとコミットメッセージの両方に入れる** ⇒ **`grep -rn DC13b docs/` がそのまま索引**になる。
  **手書きの索引表は必ず腐る**(ahc069 の索引は自ら「節番号は分割前のまま」と書いており、欠番が 2 つあった)。
- 🔴 **ID を振るのは「多くて・名前が無くて・後で指し直すもの」だけ。**

  | 対象 | 個数 | 既に名前があるか | 住所 |
  |---|---|---|---|
  | **設計上の選択**(register の行 ＝ 次の一手の候補) | 多い | 無い | **`DC05`**(**D**esign **C**hoice。枝分かれは `DC05b`) |
  | **否定結果**(前提つき) | 多い | 無い | **`NG27`**(**N**o **G**ood) |
  | **測定 1 本** | 多い | 無い | **`EX001`** ── 🔴 **族に紐付けない全体通番**(`docs/EVIDENCE.md`、育ったら `docs/evidence/<族>.md` の見出しに振る) |
  | 過去回調査の軸 | 少ない | — | `SV3`(1 ファイル内の節なので番号でよい) |
  | **証拠の族 / 版 / 提出** | **少ない** | **有る** | 🔴 **ID を作らない。** `evidence/repack.md` / `113_best2` / 提出#18 |

- 🔴 **少なくて既に名前があるものに ID を作らない。** 別名を作った瞬間に二重管理になり、しかも
  **通番は参照先で意味が読めない**(`A` も `EV04` も「順番」しか意味せず、読むたび索引を引く羽目になる)。
  **容器(ファイル・族)の住所はパスでよい** ── 自己記述的で、名前空間を作らないので衝突もしない。
- 🔴 **ID は「2 文字の記号 ＋ 2 桁ゼロ詰めの通番」。単一文字 (`A` `B` `C` …) は使わない。**
  種類が増えると**必ず名前空間が衝突する**(ahc069: 証拠の族・過去回調査の軸・register が**3 つとも独立に
  `A B C …` を使い、`C` だけで「形族」「幾何」「設計上の選択」の 3 つを指していた** ── しかも
  索引に「**C. 形族・位置評価 族(register C6/C10)**」と、1 行の中に両方の意味で書かれていた)。
  ⚠ 短い記号は **env 名とも衝突する**(AHC の repo で最も密な大文字トークンは env 名。
  ahc069 の `RP` は `RPM`/`RPK`/`RPTL`/`RPEW`… **14 個**と綴りが被っていた) ⇒ **記号の使用先を絞る**。
- 🔴 **ID に容器(ファイル・族・節)を符号化しない。容器は動く。**
  ahc069 では 1 ファイルを 9 個に割った ── `RP07` のような形は**付け替えた瞬間に壊れる**。
  しかも**書く瞬間に「どの族か」の判断を強制する**(本戦中にその判断が破綻して 4 本が迷子になった)。
  **`EX001` なら再配置しても不変で、追記時の判断もゼロ。**
- ⚠ **`CLAUDE.md` はリポジトリ直下に置く**(ハーネスが `./CLAUDE.md` を自動読込するため移動できない)。
- **`AGENTS.md`(Codex 等の入口)は「このファイルを読め」と言うだけの薄いシム**。**規約とハーネス差分以外を書かない**
  ── ルールを写した瞬間に二重管理になる。
