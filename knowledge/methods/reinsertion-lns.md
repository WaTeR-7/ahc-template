# 操作列の入れ直し LNS — 数対象を操作列から抜き、残りを固定して 1 つずつ最適に入れ直す

**一言で**: 解を**操作列そのもの**で持つ。対象を数個まとめて操作列から抜き、**残りの操作列を固定したまま**、
1 つずつ「追加の操作回数が最小の経路」（時刻順の DP）で入れ直す。長さが元以下なら受理する。
**最小化するのは出力列の長さそのもの**で、評価関数を持たない。

## 他の手法との対比（**ここが一番大事**）

| | ビーム / 計画の焼きなまし | 時空間 BFS（構築） | **操作列の入れ直し LNS** |
|---|---|---|---|
| 何を最適化するか | 評価関数 ／ 計画を実行器に通した手数 | 出力列の長さ | **出力列の長さ** |
| 解の表現 | 盤面 ／ 計画（道 ＋ 順位） | 操作列（1 対象ずつ足していく） | **操作列（全対象が入った完成した解）** |
| 1 回の操作 | 1 手 ／ 計画の 1 か所 | 1 対象を足す | **K 対象を抜いて、1 つずつ入れ直す** |
| 方向を決めるもの | 推定（評価関数・規則） | 厳密な残りコスト | **厳密な最適応答**（1 対象については推定なし） |
| 時間を増やすと | 伸びる（ただし評価の天井まで） | **ほぼ伸びない**（1 回が厳密） | **伸び続ける**（まとめて抜く近傍があるとき。無いとすぐ止まる） |
| 途中の悪化 | 評価の谷として見える | — | **見えない**（抜いて入れ直した結果の長さだけを比べる） |

- **[時空間 BFS](spacetime-bfs.md) との違いは「置く位置」**。あちらは空の列から 1 対象ずつ確定していく構築で、
  先に入れた対象は後から入る対象の操作を使えない。こちらは**完成した解の上で、何度でも抜いて入れ直す**ので、
  その非対称を繰り返しで均す。DP の中身（乗る 0 手／挿す 1 手）は同じ。
- **計画 ＋ 規則の実行器（[plan-executor-sa](plan-executor-sa.md)）との違いは「規則が無い」こと**。
  計画と操作列の間に規則が挟まると、規則が出す損は探索から動かせない。操作列を直接持てば、その損を出力の上で取り返せる。

## いつ使うか（構造カルテの軸）

**必須**:
- **軸1 = 操作列** ／ **軸2 = スコアが列の長さ**（時空間 BFS と同じ）
- **軸3a = 1 操作が複数の対象を動かす**（既存の操作に乗れる ＝ 0 手の遷移がある）
- **1 対象を抜いた残りの操作列が、そのまま（またはほぼ）正当な操作列になること**。
  抜くと壊れる制約があるなら、その制約を「入れ直す経路の必須条件」に書けること
  （→ [抜いた途中の世界では制約の不足を記録して、後から埋める](../techniques/provisional-world-deficit.md)）

**強く効く条件**:
- **軸4 = 独立解の下限が上位に届かない**（共有が主戦場）
- **軸5 = 干渉が「対象の並び順」など、1 対象の状態に畳める**（DP の状態に入れられる）
- **良い手順が一時的な悪化を含む**（1 手ずつの評価では拾えない。→ [性質 × 解法の表](../techniques/property-method-table.md)）
- 初期解を作る別の解法が既にあり、**その解に「規則や評価が固定した損」が残っている**

**向かない**: 1 対象を抜くと残りが大きく壊れる（操作が対象の集合ではなく盤面全体に作用する）／
1 対象の状態が小さく畳めない（DP が回らない）／ スコアが列の長さではない。

## 中身（状態・遷移・評価）

- **解**: 操作列。各操作を「どのマスから何匹」ではなく**「どの個体が動くか」**で読み替えて持つ
  （こうしておくと、個体 x を抜いた列が定義できる）。
- **抜く**: x しか動かない操作は消える。x が相乗りしていた操作は x 抜きで残る ⇒ **残りの操作列**（その 1 手 1 手が DP の「出来事」）。
- **入れ直しの DP**: 残りの操作列を前から 1 手ずつ進めながら、x の状態ごとに「そこに着くまでの最小の追加手数」を更新する。
  - **状態** = x の位置と、干渉を決める小さな量（ahc072: マス ＋「自分の上に何匹乗っているか」）。
  - **0 手の遷移**: 待つ ／ 既存の操作に運ばれる（一団の中に居る）／ 既存の操作に加わる（一団のすぐ下から）／ 上から着地されて位置が変わる。
  - **1 手の遷移**: x が自分で動く（ahc072: x が一番上のとき x だけが跳ぶ。足元の全員が土台）。
  - **終端**: x がゴールに着く（ahc072: 自分の色の巣で一番上になる）。
  - 可否は**条文の条件を x 入りの世界の量で**判定する（→ 落とし穴 4）。
- **受理**: 全員を入れ終えた列の長さが**元以下**なら受理（**同点も**）。同点の経路が複数あれば無作為に選ぶ。
- **評価関数は無い。** 比べるのは操作列の長さだけ。

## 骨格

```
sol = 初期解の操作列（別の解法で作る。全対象がゴールしていること）
while 時間がある:
    x  = 無作為な 1 対象
    xs = [x] + (x と同じ操作で一緒に動いたことのある対象から無作為に K−1 個)
    rest = sol から xs を抜いた列                 # 抜いた者に依存する制約の「不足」を記録
    for y in shuffle(xs):
        path = DP(rest, y, 上限 = 元の長さまでの残り [+1])   # 最小追加手数。必須条件つき
        if path が無い: 捨てて次の試行へ
        rest = rest に path を織り込む
    if 不足が全部埋まり、公式の規則で頭から再生できて、len(rest) ≤ len(sol) [+1]:
        sol = rest
    N 回ごと: sol の操作の順番を、同じ場所に触る操作どうしの順は保ったまま無作為に並べ替える
出力 = 最良の列を公式の規則で 1 手ずつ再生したもの
```

## 実装の要点 / 調整点

| ノブ | 意味 | ahc072 での値と測定 |
|---|---|---|
| **まとめて抜く数 K** | 1 回の試行で抜く対象の数 | **7 → 6 → 5 と時間で下げる**。大きいほど 1 回の受理が大きいが、1 回が重く不成立も多い。🔴 **最適は DP の速さで動く**（3.7 倍速くしたら 5 → 6〜7、「時間で下げても差なし」が +0.6% に反転） |
| **抜く相手** | x の連れの選び方 | **一緒に動いたことのある者 > 初期位置が近い者 > 無作為**（→ [interaction-group-neighborhood](../techniques/interaction-group-neighborhood.md)） |
| **同点の受理** | 長さが同じ結果を受理するか | **必須**。受理しないと得が +6.56% → +2.18% に落ちる（→ [plateau-walk](../techniques/plateau-walk.md)） |
| **+1 の受理** | 元より 1 手長い結果を受理するか | 試行の 4 割で、最良 + 1 までだけ。**小さい入力では +1%、大きい入力では −0.74%**（→ [bounded-uphill-acceptance](../techniques/bounded-uphill-acceptance.md)） |
| **順番の並べ替え** | 操作列の線形の順を取り替える頻度 | 100 試行ごと。+0.28〜0.39%（頻度 10〜1000 は平ら） |
| **初期解に回す時間** | 初期解の解法と入れ直しの配分 | 初期解 25% 以下・入れ直し 75% 以上。**初期解は良さより早さ**（→ [stage-role-change](../techniques/stage-role-change.md)） |

**速さ**（ahc072 で合わせて 3.7 倍。出力を変えない範囲で）:

1. **費用の上限を 0 → 1 → 2 → 4 … と上げながら DP を回し、見つかった所で止める**（−42%）。受理されるのは追加 0〜1 手の経路がほとんどなので、小さい上限で済む。
2. **必要条件での枝刈り**（−17%）: 費用が上限ちょうどの状態は、「そこから既存の操作に乗るだけでゴールに着ける」位置・時刻でだけ作る
   （乗り継ぎだけで着ける最後の時刻を、位置ごとに前計算する）。
3. **操作列の再生をまとめる**（プロファイルで全体の半分がここだった。区間ごとのタイマーでは見えず、[命令の番地を採る方式](../techniques/sampling-profiler.md)で分かった）。
4. 🔴 探す順・範囲を変える高速化は乱数の列が変わるので byte 一致が取れない ⇒ **同じ入力で旧・新の最小費用が一致することを assert**
   （→ [equivalence-by-assert](../techniques/equivalence-by-assert.md) の実例 ③）。

**正当性**:

- **出力は、公式と同じ規則の `apply` で頭から 1 手ずつ再生して作る**。DP の中の規則と食い違った試行は捨てる（直した後は 0 件）。
- 入れ直しの途中で panic しても解を出せるよう、**直前の正当な列を控えておく**。

## 落とし穴

1. 🔴 **1 対象だけの入れ直しは、数 ms〜数百 ms で止まる。** 相乗りしている 2 対象の片方を抜いても、残った方がその操作を使い続けるので操作が消えない。
   ここに時間を渡しても無駄（800 ms 渡すと下がった）。**まとめて抜く近傍を足して初めて、時間で伸び続ける探索になり、主役が入れ替わる**
   （初期解 : 入れ直し = 1000 : 200 → 300 : 900）。
2. 🔴 **「後処理として載せても効かない」という過去の否定に引きずられない。** ahc068 の記録は「貪欲の後に走らせると意味がない（−0.52%）」で、
   **何を固定して何を入れ直したのかという前提が書かれていなかった**。ahc072 では同じ型の DP が、完成した解の後処理として +6.8%、まとめ抜きを足して +11%。
   否定は前提つきで残す。
3. **抜くと壊れる制約を見落とす**。ahc072 では x が土台だった跳躍が、x を抜くと飛べなくなる ⇒「その時刻に x がその土台に居る」を経路の必須条件にする
   （必須なしだと +6.56% → +5.56%）。
4. 🔴 **「x を抜いた世界」の量で、条文の量を代用しない。** 可否の `if` が条文と同じ形でも、代入している高さ・匹数が x 抜きの世界の値だと条文より狭くなる
   （ahc072: 直して +0.4〜0.6%。→ [approximated-world-variable](../techniques/approximated-world-variable.md)）。
5. 🔴 **DP は操作列の線形の順を固定している。** x が乗れるのは、列の上で「x がそこに着いた時点より後ろ」に書かれた操作だけ。
   関係のない操作がたまたま先に書かれているだけで、乗れるはずの操作が見えなくなる ⇒ 順番の並べ替え（上の表）。
6. **「印 = 番号」で集合を表す一時配列は、呼び出しをまたいで一意な値にする**（手の番号 + 1 を印にして、前の呼び出しの印が残った。
   出力は検査を通るので数字に出ず、別のモードの panic で見つかった）。
7. **局所解から出る仕組みは、1 回の試行を重くすると負ける**（ahc072 で線に届かなかった 3 本）:
   全員を入れた後にもう 1 周入れ直してから判定する（不成立の 15〜26% を救うが、回数が 15〜34% 減る）／
   試行の一部を大きい K にする（混ぜるほど回数が減る）／ 停滞したら最良へ戻して大きい K・悪化を許す 1 回を入れる（3 集合で +0.14%、`t` 3.8）。
   ⚠ 一番小さい入力の帯だけは正の向きだった（全体の約 1 割）。
8. **抜く組に重みを付けても当たりは大きくは増えない**（時刻の層の中で 1.2〜1.4 倍）。当たりは「どの組か」より「いつ試すか」（序盤）で決まる。
9. **初期解の解法の設定は、入れ直しの後の値で測り直す**（振り分けの閾値・評価の重みが動いた。実際の手数を直接最小化する探索の設定は動かなかった）。

## 実績

- **AHC072**（塔になって跳ぶスライムを色ごとの巣へ帰す ／ 手数の最小化・相対評価）: **41 位**。
  配送計画の焼きなまし ＋ ビームの振り分け（当時 127 位相当）に、1 対象ずつの入れ直しで **+6.8%**、まとめ抜きを足して **+10.95%**（46 位）。
  以後の上積み（高速化・+1 の受理・並べ替え・初期解を早く渡す・狭い点の修正）で合わせて約 +5%。
  **初期解を「1 対象ずつ歩かせる貪欲」に替えても最終形の 3% 以内** ＝ スコアのほとんどはこの手法が出している。
  内訳は [`contests/ahc072.md`](../contests/ahc072.md)。
- 未着手で残したもの: x が他の対象を連れて動く 1 手 ／ 順番に依らない DP（前後関係のグラフの上で探す）／ 入力の帯ごとの K。
  1 位との差（1 割あまり）は「抜く対象の選び方」と「初期解の構築」にあった（ユーザーの所見）。

## 別名・関連

**LNS（Large Neighborhood Search）/ destroy & repair / ruin & recreate**。配送計画（VRP）の「客を数人抜いて、最良の位置に挿し直す」と同じ型で、
違いは**挿し直しが厳密な最短路（時刻順の DP）**であること。DP の部分は time-expanded graph の最短路（[時空間 BFS](spacetime-bfs.md)）。
