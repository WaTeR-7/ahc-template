# 計画 ＋ 規則の実行器の焼きなまし — 解を「計画」で持ち、規則で操作列に落とした実際の値で焼きなます

**一言で**: 操作列を直接は持たない。**「誰がどの道を通るか」という計画**を解にして、**規則の実行器**が計画を操作列に落とす。
焼きなましのコストは、実行器が出した操作列の**実際の長さ**。

## 他の手法との対比

| | 1 手ビーム | **計画 ＋ 実行器の焼きなまし** | 操作列の入れ直し LNS |
|---|---|---|---|
| 解の表現 | 盤面の列 | **計画（各対象の道 ＋ 順位の変数）** | 操作列 |
| 方向を決めるもの | 1 手ごとの評価 | **最後まで実行した実際の値** | 厳密な最適応答 |
| 一時的な悪化を含む手順 | × | **○**（道として先に決めてしまう） | ○ |
| 「いつ・どの順で」 | ○（1 手ずつ決める） | **△ 実行器の規則が決める**（探索から動かせない） | ○ |
| 評価 1 回の重さ | 軽い（差分） | **重い（全体の再生）** ⇒ 大きい入力で反復が足りない | 中（1 対象の DP） |

## いつ使うか

- **向く**: 得が数手後に返る手順（合流・待ち合わせ）が主戦場で、1 手の評価では拾えない ／ 計画から正当な操作列を**必ず**作れる規則が書ける ／
  入力が小さく、評価（再生）を数万〜数十万回まわせる。
- **向かない**: 🔴 **計画と実際の値の間を規則が決めていて、その規則が損を固定するとき**（ahc072: 土台の確保と塔の中の順序）。
  時間を 256 倍にしても上位に届かなかった。入力が大きいと反復が足りない。
- **今の位置づけ**: 操作列を直接直せる後段（[入れ直し LNS](reinsertion-lns.md)）があるなら、**小さい入力の初期解**として使う。

## 中身（ahc072）

- **計画**: 各対象の道 = 跳び（出発マス・向き・長さ）の列。同じ跳びを選んだ者どうしが「相乗りの予定」。跳びごとに整数の**優先度 P**（±8）。
- **実行器**（毎手、決定的に 1 つ選ぶ）: 各塔の一番上の「次の跳びが同じ連なり」を候補にして、
  **準備できている（同じ跳びを通る仲間が揃っている）→ P → 匹数 → マス番号（同点崩し）** の順で選ぶ。
  条件を満たせないときは跳びを縮める・逃がすなどして、**どんな計画からでも正当な操作列を作る**。
- **コスト**: 実行器が出した操作列の長さ（実際の手数）。
- **初期の計画**: 各対象の最短路。
- **近傍**: 道の引き直し（1 対象）／ P を ±1 ／ **一団ごとの跳躍化・分解** ／ **一団ごとの付け替え**（ある区間を一緒に通る全員を、まとめて別の道へ）。

## 実装の要点 / 調整点（ahc072 の測定）

| ノブ | 分かったこと |
|---|---|
| **コストに何を使うか** | 時刻を無視した楽観的なモデル（道の重なり = 相乗りできたと数える）から、**実行器の実際の手数**に替えて 8.04 → 4.90 手/匹。**評価を真の値に近づける変更が一番大きい** |
| **順位の変数** | 順序を規則まかせから、跳びごとの優先度 P を焼きなます形にして **+10.4%**。第 2 の優先度を足しても伸びない（時間 16 倍でも）＝ 捨ててよい自由度 |
| **初期の計画** | 楽観的なモデルで作り込んだ計画より、**最短路から始める方が +13.3%**。よその解法（ビーム・貪欲）の解から取った道は、値が良くても焼きなまし後に −2〜−5%（その解法の決め打ちが、こちらの近傍で崩せない局所になる） |
| **近傍** | 🔴 **1 対象だけを動かす近傍（区間の引き直し・合流）は ±0。一緒に動く全員をまとめて動かす近傍だけが効く**（跳躍化 +6〜7%・付け替え +3%）。ただし一度に変える量が大きすぎるもの（一団ごとの合流）は負ける（→ [interaction-group-neighborhood](../techniques/interaction-group-neighborhood.md)） |
| **近傍の費用の数え方** | 一団ごとの付け替えの道を選ぶ費用を「1 対象ぶん」から「一団の人数ぶん」に直して +0.27%、**直結する設定（その近傍の割合）を一緒に上げて +1.4%** |
| **温度** | 開始 1 → 終了 0.1（手数の単位）が両側とも局所最適 |
| **同点の受理** | 🔴 **必須**。同点を確率 0.25 / 0.5 で断るだけで −0.5 / −1.2%。第 2 の目的を辞書順で足すと、目的の中身に関係なく負ける（→ [plateau-walk](../techniques/plateau-walk.md)） |
| **速さ** | 律速は評価（再生）。「たまにしか起きないはず」の非常手段が、**探索の途中の悪い計画では** 1 回の評価に 20〜40 回起きていて評価時間の 28〜66% ⇒ 入力だけで決まる量を前計算して −51〜−63%、反復 1.5 倍で +1.8% |
| **時間の感受性** | 倍ごとに +1.8〜2.9%（256 倍まで頭打ちなし）。🔴 ただし強い後段を入れた後は、後半の半分の時間が +0.9% しか効かない ⇒ 時間を 4 分の 1 に切って後段へ回して +5% |

## 落とし穴

- 🔴 **探索が実際の値で自分で決めていることに、外から規則で口を出すと負ける。** 実行器の規則（待つ範囲・土台として残る・一団を割る・強制の選び方・行き先の違う者も運ぶ）を変える **10 本が全滅**（−2〜−8%）。
  診断で見えた「無駄」（当分来ない相手を待っている、など）は事実でも、**焼きなましは今の規則に合わせて計画を作り込んでいる**ので、規則を直すと合わなくなる。
  同点崩し（マス番号の小さい方）ですら、変えると必ず悪化した。
- 🔴 **楽観値と実際の差を「実行器の損」と読まない。** 最終の計画の道が重なる所を全部相乗りできたと数えた値と、実際の手数の差は +21% あったが、
  焼きなましは実際の手数で計画を選んでいるので、道の重なりは相乗りを狙ったものとは限らない。計画を固定して実行だけを探索しても 0〜2 手しか縮まなかった。
- **「楽観的なつもり」のモデルが悲観的になる**。合流と跳躍の無い配送計画（塔が寄り道して拾う）は、ビームの実際の解より 16% 悪かった。
  天井として使う前に、上位の実解・自分の実解を本当に下回るかを確かめる。
- **差分の評価は上限が小さい**。実行器が全体の貪欲な選択なので、1 か所の変更の影響が軌跡の大部分に広がる（上限 1.4〜1.7 倍 ⇒ 実装しなかった）。
- **別の乱数の種に、主の乱数の出力をそのまま使わない**（道の引き直しの揺らぎの種がこれで、特定の 2 入力だけ探索が詰まり手数 2 倍。splitmix64 で混ぜる）。
- **分けて解いて合わせる**（色ごとに小さい問題として焼きなます）は −3〜−4%。合わせたときの詰まりを解く仕組みが無い。

## 実績

- **AHC072**: 9/30〜10/2 の主役。ビーム比で暫定 50 ケースの絶対スコア 12888 → 12220。最終形では **M ≤ 60 の初期解**（締切の 25% まで）と、
  ビームが解を出せなかったときの逃げ道。入れ直し LNS の初期解としての設定は、6 軸の両側を測って全部局所最適（実際の値を直接最小化する探索の設定は、役目が変わっても動かない）。

## 別名・関連

indirect encoding（間接表現）＋ decoder / schedule generation scheme。ジョブショップの「優先度の列を焼きなまして、規則でスケジュールに落とす」と同じ型。
道具は `lib/anneal.rs`・`lib/dijkstra.rs`。
