# 時空間BFS — 出力列を時間軸として扱い、対象を (空間 × 時刻) の最短路で運ぶ

**一言で**: 既に出力した操作列を**時間軸**とみなし、次の対象を「**既存の操作に乗る（0手）／操作を挿す（1手）**」
の最短路で家まで運ぶ。**最小化するのは出力列の長さそのもの**で、解の「質」という概念が無い。

## ビームサーチ / SA との対比（**ここが一番大事**）

| | ビーム / SA / chokudai | **時空間BFS** |
|---|---|---|
| 何を最適化するか | **解の質**（評価関数を登る） | **出力列の長さ**（回数そのもの） |
| 状態 | 解の候補（盤面全体） | **(1対象の位置 × 操作列の時刻)** |
| 遷移 | 近傍・候補手 | **乗る（0手）／挿す（1手）** |
| 方向を決めるもの | **ヒューリスティックな評価関数**（推定） | **厳密な残りコスト**（逆BFS 1回で計算） |
| 時間を増やすと | 反復が増えて伸びる | **ほぼ伸びない**（1回が既に厳密。伸びるのは共有の質だけ） |
| 全体の形 | 候補集合を保持して更新 | **1対象ずつ永久に確定していく構築** |

**評価関数の席に「厳密な残りコスト」が座る**のが構造的な違い。1つの対象だけを見れば残りコストは厳密に
計算できる（他の対象を無視してよい）ので、**推定が要らず、探索も要らない**。
⇒ ahc068 で TL を 17 倍にしても合計 T が −2.30% しか動かなかったのはこのため（軸8）。
**この族では「反復を増やす」が効かない。効くのは「1操作を何対象で共有できたか」だけ。**

## いつ使うか（構造カルテの軸）

**必須**:
- **軸1 = 操作列**（時間軸が要る。配置・割当の問題には適用できない）
- **軸2 = スコアが列の長さ**（操作回数・手数）。品質という軸が無い／薄い
- **軸3 = 1操作が複数の対象を動かす**（＝乗る価値がある。巻き込みが無いなら共有できない）

**強く効く条件**:
- **軸4 = 独立に解いた下限が上位スコアに届かない** ⇒ 共有が数学的に必須（判定法は
  [ride-along](../techniques/ride-along.md)）
- **軸5 = 決定が干渉する**（1つずつ確定していく構造と噛み合う）
- **軸8 = 感受性が低い**（探索で買えない ⇒ 1回を厳密にする方向が正しい）

**向かない**: 出力が静的な配置／スコアが品質で決まる／1操作の副作用が無い（＝乗れない）。

## 中身（状態・遷移・評価）

> **「状態・遷移・評価」を書くのはここ**（枠組みを選んだ後）。カルテの段でこの3語を先に埋めると、
> 「探索で解く」という前提が入ってしまう。

- **状態**: `(対象の位置 p, 操作列の時刻 t)`。t は既存の操作列 `ops[0..T]` への添字。
- **遷移**:
  - **乗る（0手）**: 時刻 t の操作が p を動かすなら `p → op_map(ops[t], p)`, `t → t+1`。無料。
    動かさない場合も、**操作の幅を広げれば動かせる**なら無料で乗れる（→ 過去改変）。
  - **挿す（1手）**: 時刻 t に新しい操作を挿入して `p → q`。コスト 1。
- **評価**: 末尾に着いた後の**厳密な残りコスト** `cost_to_home[p]`。

## 骨格

```
h[T][p] = cost_to_home[p]                       # 末尾からは自力で帰る（厳密）
h[t][p] = min( h[t+1][ride(p)] ,                # 乗る: 0手
               1 + min_{q∈N(p)} h[t][q] )       # 挿す: 1手（同一時刻内での移動）
```

`h[0][現在位置]` がこの対象を運ぶ最小手数。経路を復元して、乗る所は幅を広げ、挿す所に操作を挿入する。

## 実装の要点

1. **挿入用の移動グラフ `N(p)` は「対象の位置」に依存しない**（壁と確定済みセルだけで決まる）。
   ⇒ **家から逆BFS 1回で全セルの `cost_to_home` が出て、乗る/挿すのどの選択をしても有効なまま**。
   これが計算量を成立させている（毎回作り直す必要がない）。
2. **コストが 0/1 しかない** ⇒ 0-1 BFS / バケットキューで解ける（優先度付きキューは不要）。
3. `h[0]` の値だけ要るなら**2層のローリング**で持てる（メモリ O(状態数)、memset も不要にできる）。
4. **時刻依存の禁止集合 `forb[t]`** が必要。時刻 t に挿入した操作が動かすのは「**その時刻にそこに居たもの**」
   なので、**確定済みかどうかを最終位置で判定すると誤り**（→ [narrow-before-verify](../techniques/narrow-before-verify.md)）。
5. **打ち切りは作業量カウンタで**。壁時計で打ち切ると解が非決定的になり、掃引の比較が壊れる。

## 調整点（env で外出しして掃引する）

| ノブ | 意味 | ahc068 での最良 |
|---|---|---|
| 適用する対象の閾値 | 残り未確定数がこれ以上の対象にだけ適用 | **下げる方が良い**（8→3）。空いた予算の配分先として掃引する（→ [endgame-gate](../techniques/endgame-gate.md)） |
| 時刻の間引き | 重い段だけ時刻を飛ばす | **8刻み**で品質同等・時間半分。**間引くのは O(N) の段だけ、O(1) の段は全解像度**（どちらかは計測で決める） |
| 作業量予算 | 決定的な打ち切り | 300,000 単位（≒1.5秒。~195単位/ms で校正） |

## 落とし穴

- **貪欲の「後」に走らせると意味がない**（ahc068: −0.52% しか出なかった）。貪欲が既に最適でない決定を
  列に確定させているため。**貪欲を置き換える位置に置く。**
- **供給側から考えると希釈される**。「この操作でついでに何対象運べるか」ではなく、
  **「この対象を進めたい ⇒ どの操作を広げる/挿す」**（需要側）から組む。
- **重い**（1対象あたり O(T × 状態数 × 近傍)）。機構が正しくても遅さが律速になる ⇒ 先に全数監査する。
- 予算を食うので**多スタート best-of とは併用できない**（net で測る）。

## 実績

- **AHC068**（20×20 の順列を矩形スワップで揃える／T の log がスコア）:
  1対象ずつの厳密ルーティングだけで est 898M → 時空間BFS を載せて **実 1,030,035,129**。
  内訳は [`contests/ahc068.md`](../contests/ahc068.md)。
  **利得の 69% は「1対象の厳密解」から**で、時空間BFS の上積みは 31%
  （＝**土台が悪いと乗せても効かない**）。

## 別名・関連

**「時空間BFS」は AHC068 の writer の呼び名。** 一般的には **time-expanded graph / time-space network**
（配車・運行計画・スケジューリングで使われる定式化）で、**「乗客を最小本数のバスで運ぶ」問題と同型**。

> **模型として持っておくと速い**: `1操作 = バス1本 / 対象 = 乗客`。バスは決まった経路を走り、
> **経路が合う乗客は無料で乗れる**。合わなければバスを1本増やす（コスト1）。**最小化するのはバスの本数。**
> ⇒ この模型に置くと「乗客の総移動距離を縮めてもバスの本数は減らない」＝ **距離を評価関数にしてはいけない**
> ことが即座に分かる（ahc068 の敗因そのもの）。
